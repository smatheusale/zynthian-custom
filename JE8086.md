> # ⚠️ IMPORTANT — MIDI CHANNEL REQUIREMENT
>
> **The JE8086 chain MUST be set to a FIXED MIDI channel (e.g. channel 1).
> It does NOT work when the chain's MIDI channel is set to "ALL" / omni.**
>
> ### Why
>
> Zynthian's MIDI routing (`zmop_set_midi_chan_trans`) collapses every
> incoming channel into ch0 when a chain is in omni mode. The JE8086 is
> in the `dsp56300_plugins` list, which forces all MIDI translation onto
> a single internal channel.
>
> The consequences in omni mode are:
>
> - **Multitimbral Dual / Split Performances lose the Lower Part.** Only
>   the Upper Part can be played, because Zynthian no longer delivers
>   anything on the Lower Part's channel.
> - **Preset switching may fail.** The engine patch dispatches Bank
>   Select + Program Change on a real channel; with omni, that target is
>   ambiguous or invalid (a recent fix uses `midi_chan_engine = 0` to
>   work around this for single-part patches, but multitimbral state is
>   still degraded).
>
> ### What to do
>
> - **Set the JE8086 chain's MIDI channel to 1** (or any other fixed
>   channel 1–16). All A/B singles, all P-bank Performances — including
>   Dual / Split — will then work correctly.
> - If you want a specific external keyboard to play the chain regardless
>   of which channel it transmits on, **do the channel remap on the
>   *input* side** (in Web Admin → MIDI Input or in the wiring profile),
>   not by switching the chain to omni.
> - This applies equally to the related firmware-emulator plugins
>   (Osirus, OsTIrus, Vavra, Xenia, NodalRed2x — all in the
>   `dsp56300_plugins` list).
>
> ### Compatibility matrix
>
> | Chain MIDI channel | A/B singles | P-bank single/WHOLE | P-bank Dual / Split |
> |---|---|---|---|
> | **Fixed (e.g. ch 1)** | ✅ | ✅ | ✅ |
> | ALL / omni            | ✅ | ✅ | ⚠️ Upper only |

This document explains how to get **The Usual Suspects' JE8086** LV2
plugin running on **Zynthian** with full preset switching, including:

- All **128 single patches** (Internal A1-1 … B8-8)
- All **64 performance patches** (Internal P1-1 … P8-8) with their
  proper Key Mode (WHOLE / DUAL / SPLIT) and arpeggiator state
- A blank `(none)` audition entry
- An `init` preset that resets Key Mode to WHOLE and turns the
  arpeggiator off — used both as a manual reset and as the base state
  for all 128 A/B single patches
- Auto-loading of `init` whenever you add a new JE8086 chain

---

## Why this is non-trivial

JE8086 is a *firmware-accurate* emulator (Roland JP-8000). Like its
siblings NodalRed2x (Nord-Lead) and VirtualJV (Roland JV-880), it
**ignores LV2 `state:state` restore for patch selection on a running
plugin instance** — saving and loading the vendor's own "default" preset
doesn't actually change the active patch.

The only mechanism that reliably switches patches on a running JE8086
instance is **MIDI Bank Select + Program Change**:

| Bank      | MSB | LSB | PC range | Patches              |
|-----------|-----|-----|----------|----------------------|
| Single A  | 0   | 0   | 0 … 63   | A1-1 … A8-8 (64)     |
| Single B  | 0   | 1   | 0 … 63   | B1-1 … B8-8 (64)     |
| Perf. P   | 0   | 2   | 0 … 63   | P1-1 … P8-8 (64)     |

The default Zynthian LV2 engine doesn't know about this — it just calls
the LV2 preset-restore code path. So out of the box, you can load a
JE8086 preset and hear no difference.

The good news: while `StateString` doesn't restore the **patch slot** on
a running instance, it **does** restore **Key Mode** and **arpeggiator
on/off**. So the trick is:

- **Patch slot** → driven by MIDI Bank Select + PC (added via a small
  Zynthian engine patch)
- **Key Mode + arp** → driven by `state:state` `StateString` inside the
  TTL (use a known-good init blob for all the singles)

## How the engine patch works

File: `engine/zynthian_engine_jalv.patch`, applied to
`/zynthian/zynthian-ui/zyngine/zynthian_engine_jalv.py`.

Five small edits:

1. **`get_preset_list`** — reads two optional new fields per cache entry:
   - `midi_bank_select`: `[msb, lsb, pc]`
   - `midi_pc`: int
   and surfaces them as `preset[1]` so the GUI carries them through.

2. **`set_preset`** — still sends the LV2 preset URI to jalv (which
   restores the `StateString` for Key Mode / arp), then dispatches MIDI
   on the processor's MIDI channel:
   - Send CC120 (All Sound Off) + CC123 (All Notes Off)
   - Send Bank Select MSB + LSB + PC (or just PC if only `midi_pc` is set)
   - Re-dispatch after a 1.5 s `Timer` so it lands **after** snapshot
     restore wires up MIDI and jalv finishes loading
   - Return `True` so the GUI follows the standard Zynthian flow (purge
     bank history, jump to `chain_control`)

3. **`(none)` blank entry** — an entry with `url: ""` hits the existing
   early-return; no MIDI sent. Add it by prepending
   `{"label": "(none)", "url": ""}` to the first bank in the cache.

4. **`proc_poll_parse_line`** — early-returns on `MIDI Out:` log lines
   because JE8086 spams one stdout line per outgoing MIDI byte; left
   unfiltered it saturates the stdout poll thread.

5. **`add_processor` + `_load_default_preset`** — auto-loads the preset
   labelled `init` from `Internal A1` every time a new JE8086 chain is
   added, so you always start from WHOLE / arp-off.

## How the preset cache is laid out

File: `cache/presets_JE8086.json` → installed to
`/zynthian/config/jalv/presets_JE8086.json`.

24 banks total:

- `Internal A1` … `Internal A8` — 8 single patches each, all with
  `midi_bank_select: [0, 0, N]` where `N` = 0..63
- `Internal B1` … `Internal B8` — same, with `[0, 1, N]`
- `Internal P1` … `Internal P8` — 8 performance patches each, with
  `[0, 2, N]`
- `Internal A1` additionally has a `(none)` blank entry prepended

Each cache entry looks like:

```json
{
  "label": "P1-1 Chariots",
  "url": "file:///zynthian/zynthian-my-data/presets/lv2/JE8086.presets.lv2/P1-1_Chariots.ttl",
  "midi_pc": 0,
  "midi_bank_select": [0, 2, 0]
}
```

> ⚠ **Critical**: the Web Admin's "**Scan for new presets**" button
> regenerates this cache via a vanilla `lilv` crawl. That **destroys**
> the `midi_bank_select` / `midi_pc` fields and drops any empty banks.
> If you ever hit that button by accident, run `./restore.sh` to put the
> kit cache back. (You can also `chattr +i` the live cache to make it
> immutable.)

## How the A/B factory bundle is built

Each of the 128 A/B TTL files (`JE8086-000_A11.ttl` …
`JE8086-127_B88.ttl`) has the same structure:

```turtle
<>
    a pset:Preset ;
    lv2:appliesTo <http://theusualsuspects.lv2/JE8086> ;
    rdfs:label "Spit'n Slide Bs" ;
    pset:bank <JE8086_BankA1> ;
    lv2:port [ lv2:symbol "enabled" ; pset:value 1.0 ] ,
             [ lv2:symbol "freeWheeling" ; pset:value 0.0 ] ;
    state:state [
        <http://theusualsuspects.lv2/JE8086:StateString> "1078.H....PzT…(base64 blob)"
    ] .
```

- The **label** is unique per slot (the JP-8000 factory name).
- The **`StateString` blob** is **the same** in all 128 — it's lifted
  from `init.ttl` and exists only to set Key Mode = WHOLE and arp = off.
- The **patch slot** is selected entirely by the engine patch's MIDI
  Bank Select + PC, using the `midi_bank_select` field in the cache.

This is what gives you "load any A/B preset and it resets to single /
WHOLE mode with arp off, then jumps to the right factory patch."

## P-bank (Performance Mode) patches

Performance Mode patches are different: each P-slot has its **own**
`StateString` captured by saving the running plugin state after dialling
in the desired Key Mode (single, dual, split), arp on/off, layers, etc.
The engine patch also sends the matching MIDI `[0, 2, N]`, so the
Performance slot gets selected on the JE8086 internal side too. The two
mechanisms agree.

To save your own Performance into a P-slot:

1. Configure the plugin GUI exactly how you want the Performance.
2. In Zynthian, navigate to `Internal Px` bank and select the slot you
   want to overwrite.
3. From the chain menu, choose **Save preset**. Keep the name format
   `Px-y Your Name` so it sorts correctly in the UI.
4. Refresh the kit afterwards (`./refresh.sh`) to capture the new TTL
   into the kit.

> ⚠ The on-screen QWERTY keyboard **strips special characters**
> (`<`, `>`, `/`, `:`, `*`, `?`, `|`, `"`) from preset names because
> they're illegal in filenames. If you want them in the display label,
> save with a safe name, then manually rename the TTL file to match the
> URL in the cache, and edit the `rdfs:label` inside the TTL to put the
> special chars back.

## Installation

### Prerequisites

1. A working Zynthian install (tested on **ZynthianOS 2601**, Raspberry
   Pi 5, V5 controller — should work on any V5-based image).
2. The **JE8086 LV2 plugin** installed from
   [The Usual Suspects](https://theusualsuspects.lv2) at
   `/usr/local/lib/lv2/JE8086.lv2/`. (This repo does **not** include the
   plugin — see [`DISCLAIMER.md`](DISCLAIMER.md).)

### Steps

```bash
# Clone the kit onto the user-data partition so it survives upgrades.
git clone https://github.com/smatheusale/zynthian-custom.git \
  /zynthian/zynthian-my-data/zynthian-custom

cd /zynthian/zynthian-my-data/zynthian-custom

# Apply: engine patch, preset cache, factory bundle, init bundle.
sudo ./restore.sh

# 11-check sanity test.
./verify.sh
```

After `restore.sh` finishes the Zynthian service is restarted. Add a
JE8086 chain from the UI; you should see 24 banks and 194 presets.

### Optional: lock the cache so a stray "Scan for new presets" can't trash it

```bash
sudo chattr +i /zynthian/config/jalv/presets_JE8086.json
# To unlock later:
# sudo chattr -i /zynthian/config/jalv/presets_JE8086.json
```

## After a Zynthian package upgrade

`zynthian-ui` upgrades will overwrite the engine file. To recover:

```bash
cd /zynthian/zynthian-my-data/zynthian-custom
sudo ./restore.sh && ./verify.sh
```

If `git apply` fails because upstream rewrote the engine, follow the
manual re-apply steps in [`RESTORE.md`](RESTORE.md).

You also need to **remove and re-add any JE8086 chain** — chains
restored from snapshots use the previously-loaded processor and won't
pick up the new engine code path until they're reinstantiated.

## Applying this pattern to other firmware-emulator plugins

The engine patch and cache layout aren't JE8086-specific:

- **NodalRed2x** (Nord Lead 2x) — has 99 patches in 4 banks, uses simple
  MIDI PC, no Bank Select needed. Add `"midi_pc": N` to each cache entry.
- **VirtualJV / JV-880** (giulioz) — uses Bank Select MSB/LSB + PC like
  JE8086. Add `"midi_bank_select": [msb, lsb, pc]`.
- **Osirus** (Access Virus emulator from The Usual Suspects) — same
  family; same approach should work, untested.

The engine patch already routes both `midi_pc` and `midi_bank_select`;
you only need a cache file per plugin and (optionally) a TTL bundle to
hold any global state you want restored at instantiation.
